# 대화 기억 저장

## 저장 위치

`D:\claude\memory\`

이 경로는 `~/.claude/settings.json`의 `autoMemoryDirectory`로 지정된 전역 메모리
디렉터리다. 사용자 전역 설정이라 모든 프로젝트가 이 폴더를 공유한다. 시스템 프롬프트에
그 세션의 메모리 경로가 따로 안내돼 있으면 그쪽을 우선한다.

## 순서

1. 지금까지의 대화를 아래 형식으로 요약한다.
2. 오늘 날짜를 확인한다. 세션 컨텍스트에 날짜가 없으면 `date +%F`로 확인한다.
3. 요약을 메모리 디렉터리에 `session-YYYY-MM-DD-<한-줄-주제-슬러그>.md` 이름으로 Write한다.
   - 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 먼저 Read해서, 이어지는 내용이면 갱신하고
     별개의 세션이면 이름 뒤에 `-2`처럼 번호를 붙인다.
4. 같은 디렉터리의 `MEMORY.md`에 한 줄 포인터를 추가한다:
   `- [세션 YYYY-MM-DD — <한 줄 주제>](session-YYYY-MM-DD-<슬러그>.md) — <짧은 훅>`
   - `MEMORY.md`가 없으면 새로 만든다. 이 파일은 목차이므로 요약 본문을 넣지 않는다.
5. 저장한 파일의 전체 경로와, 메모리 디렉터리의 파일 개수가 몇 개에서 몇 개로 늘었는지
   사용자에게 알려준다.

## 파일 형식

```markdown
---
name: session-YYYY-MM-DD-<슬러그>
description: <한 줄 요약 — 나중에 관련성 판단에 쓰인다>
metadata:
  type: project
---

날짜:
주제:
결정한 것:
아직 안 끝난 것:
다음에 할 것:
기억할 사실: (파일 경로, 이름, 숫자, 사용자의 선호)
```

관련된 다른 메모리가 있으면 본문에서 `[[메모리-이름]]`으로 링크한다.

## 규칙

- 사실만 적는다. 추측이나 각색은 넣지 않는다.
- 날짜는 "어제", "지난주" 같은 상대 표현 대신 절대 날짜로 적는다.
- 비밀번호, API 키, 토큰 값은 절대 본문에 적지 않는다. "키는 설정 파일에 있음"처럼 위치만 적는다.
- 저장에 실패하면 완료했다고 말하지 말고 오류 내용을 그대로 보여준다.
